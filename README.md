## What each group fills in

Each group file follows the same structure:

1. **Group members** – who is in your group.
2. **About our data** – extra details about your dataset (formats, size, metadata, etc.).
3. **Making our data FAIR** – how you will make the data Findable, Accessible, Interoperable and Reusable.
4. **Where we will deposit the data** – repository, access level, licence and cost.
5. **Where we aim to publish** – journals or preprint servers, open access route and cost.
6. **Where we will put our software / code** – platform, archiving/DOI, licence and documentation.
7. **Ethical, legal or practical barriers** – anything that limits how open your data can be.

## How to contribute

1. **Only edit your own group's file** (e.g. `group/group-2.md`) – this avoids editing conflicts.
2. Replace the `...` placeholders with your answers. Add extra rows to tables if you need them.
3. Make your changes in a **branch** or **fork**, then open a **Pull Request** with a short description (e.g. "Group 2: added FAIR plan").
4. Your instructor will review and merge the changes.

> Not sure how? Open your group's file on GitHub, click the ✏️ pencil icon, edit, and choose *"Create a new branch for this commit and start a pull request"*.

### Markdown table tips

- Each table row must stay on **one line** – don't press Enter inside a cell.
- Every row needs the same number of `|` separators as the header row.
- Use the **Preview** tab on GitHub to check your tables render correctly before submitting.
